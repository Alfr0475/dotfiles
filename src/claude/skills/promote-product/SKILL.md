プロダクトリポジトリへの移行作業を行います。
途中で確認や質問はせず、以下のステップをすべて完了させること。

## 引数の解釈

スキル起動時の引数を以下のように解釈する：
- 第1引数: ideas-vault 内のプロダクトディレクトリパス（例: `/path/to/ideas-vault/products/003-mahjong-danger-checker`）
- 第2引数: 移行先プロダクトリポジトリのルートパス（例: `/path/to/mahjong-danger-checker`）

どちらかが指定されていない場合のみ、ユーザーに確認する。

## Step 1: 設計ドキュメントの読み込み

以下のファイルをすべて読む：

- `<プロダクトディレクトリ>/README.md`
- `<プロダクトディレクトリ>/docs/` 配下の全ファイル

## Step 2: 移行先リポジトリの状態確認

移行先リポジトリで以下を確認する：

```bash
git -C <移行先> log --oneline
git -C <移行先> branch -a
ls <移行先>
```

- コミット履歴が空（初回コミット前）または初回コミットのみであることを確認する
- `docs/` ディレクトリが存在しない場合は作成する

## Step 3: 設計ドキュメントの配置

`<プロダクトディレクトリ>/docs/` 内の全ファイルを `<移行先>/docs/` にコピーする。

また、`<プロダクトディレクトリ>/README.md` を `<移行先>/docs/product-overview.md` としてコピーする。

## Step 3.5: 開発プレイブックの配置

`<移行先>/docs/開発プレイブック.md` を以下の内容で生成する。
このファイルは、このプロダクトリポジトリ上でのAI駆動開発の進め方を定義する。

---

# AI駆動開発プレイブック（実装フェーズ用）

> このプロダクトはAI駆動開発プレイブックに沿って開発する。
> フェーズ1〜4（設計）はideas-vaultで完了済み。このリポジトリではフェーズ5以降を行う。

## 設計原則

**コンテキストはドキュメントで持つ**
会話セッションは揮発する。`docs/` と `CLAUDE.md` を読めば状態を復元できる状態を常に維持する。
「文書を読めば分かる状態」を常に保つことがAI駆動開発の前提。

**仕様が不明な箇所は実装前に確認する**
仕様書に答えがない場合は推測で実装せず、ユーザーに確認してから進める。

**仕様書はAIが迷った箇所を追記して育てる**
実装中に気づいた仕様の曖昧さはユーザーに伝え、合意後に `docs/` を更新する。

## 役割分担

| 担当 | 役割 |
|------|------|
| 人間 | 意思決定・仕様承認・レビュー・最終判断 |
| Claude Code | 実装・提案・仕様の不明点の指摘 |

## タスク定義の形式

各タスクは以下の5項目で定義する。

| 項目 | 説明 |
|------|------|
| 入力 | このタスクを始めるために必要なもの |
| 出力 | このタスクが生み出すもの |
| プロセス | どうやって作るか |
| 担当 | 人間 / Claude Code |
| 完了条件 | 出力が次のタスクに渡せる状態になったと判断できる基準 |

## Step 6: develop ブランチの作成と切り替え

```bash
git -C <移行先> branch -a
```

`develop` ブランチが存在しない場合のみ作成して切り替える：

```bash
git -C <移行先> checkout -b develop
```

すでに `develop` ブランチが存在する場合はそのまま切り替えるだけ：

```bash
git -C <移行先> checkout develop
```
